Challenges & Context

Business Problem

Retail executive leadership struggled with manual, delayed reporting and zero cross-channel visibility.

Challenge 1

Fragmented Data Silos

Transaction records and inventory snapshots lived in isolated operational databases, making cross-functional reporting slow and prone to errors.

Challenge 2

Slow Monthly Reporting

Monthly sales reconciliation relied on manual spreadsheet compilation, taking up to 10 days after month-end close to produce executive summaries.

Challenge 3

Margin Visibility Blindspots

Leadership lacked visibility into true net profitability across individual products, regional store types, and customer loyalty tiers.

Challenge 4

Inconsistent MoM Tracking

No standardized time-intelligence logic existed to track month-over-month sales trends and inventory turnover rate benchmarked against targets.

Database Engineering

PostgreSQL & SQL Highlights

Production-ready SQL transformations, indexes, constraints, and analytical reporting views.

sql/01_create_schema.sql 
-- Normalized PostgreSQL relational tables for retail sales analytics
CREATE TABLE IF NOT EXISTS orders (
    order_id        BIGSERIAL PRIMARY KEY,
    order_number    VARCHAR(20) NOT NULL UNIQUE,
    customer_id     INTEGER     NOT NULL REFERENCES customers(customer_id),
    store_id        INTEGER     NOT NULL REFERENCES stores(store_id),
    order_datetime  TIMESTAMP   NOT NULL,
    order_channel   VARCHAR(20) NOT NULL CHECK (order_channel IN ('In-Store','Online','Mobile App')),
    payment_method  VARCHAR(20) NOT NULL CHECK (payment_method IN ('Card','Cash','Digital Wallet','Gift Card')),
    order_status    VARCHAR(20) NOT NULL DEFAULT 'Completed' CHECK (order_status IN ('Completed','Refunded','Cancelled'))
);
CREATE INDEX idx_orders_customer ON orders(customer_id);
CREATE INDEX idx_orders_datetime ON orders(order_datetime);

CREATE TABLE IF NOT EXISTS order_items (
    order_item_id       BIGSERIAL PRIMARY KEY,
    order_id            BIGINT        NOT NULL REFERENCES orders(order_id) ON DELETE CASCADE,
    product_id          INTEGER       NOT NULL REFERENCES products(product_id),
    quantity            INTEGER       NOT NULL CHECK (quantity > 0),
    unit_price_at_sale  NUMERIC(10,2) NOT NULL CHECK (unit_price_at_sale >= 0),
    unit_cost_at_sale   NUMERIC(10,2) NOT NULL CHECK (unit_cost_at_sale >= 0),
    discount_pct        NUMERIC(5,2)  NOT NULL DEFAULT 0 CHECK (discount_pct BETWEEN 0 AND 100)
);
sql/02_seed_demo_data.sql 
-- Data Generator Routine for Simulated Retail Transactions (50,000+ Items)
DO $$
DECLARE
    v_i INT;
    v_order_id BIGINT;
BEGIN
    FOR v_i IN 1..18000 LOOP
        INSERT INTO orders (order_number, customer_id, store_id, order_datetime, order_channel, payment_method, order_status)
        VALUES (
            'ORD-2022-' || LPAD(v_i::TEXT, 6, '0'),
            1 + (v_i % 500),
            1 + (v_i % 9),
            '2022-01-01 08:00:00'::TIMESTAMP + (v_i * INTERVAL '50 minutes'),
            CASE WHEN v_i % 3 = 0 THEN 'Online' ELSE 'In-Store' END,
            'Card',
            'Completed'
        ) RETURNING order_id INTO v_order_id;

        INSERT INTO order_items (order_id, product_id, quantity, unit_price_at_sale, unit_cost_at_sale, discount_pct)
        VALUES (v_order_id, 1 + (v_i % 10), 1 + (v_i % 4), 199.99, 85.00, CASE WHEN v_i % 5 = 0 THEN 10.0 ELSE 0 END);
    END LOOP;
END $$;
sql/03_transformations.sql 
-- Sales line transformation calculating net revenue and gross profit
CREATE OR REPLACE VIEW vw_sales_line AS
SELECT
    oi.order_item_id,
    o.order_id,
    o.order_number,
    o.order_datetime,
    DATE_TRUNC('day', o.order_datetime)::DATE AS order_date,
    c.customer_id,
    s.store_name,
    r.region_name,
    p.product_name,
    pc.category_name,
    oi.quantity,
    oi.unit_price_at_sale,
    oi.discount_pct,
    ROUND(oi.quantity * oi.unit_price_at_sale * (1 - oi.discount_pct / 100.0), 2) AS net_revenue,
    ROUND(oi.quantity * oi.unit_cost_at_sale, 2) AS total_cost,
    ROUND(oi.quantity * oi.unit_price_at_sale * (1 - oi.discount_pct / 100.0) - oi.quantity * oi.unit_cost_at_sale, 2) AS gross_profit
FROM order_items oi
JOIN orders o ON o.order_id = oi.order_id
JOIN customers c ON c.customer_id = o.customer_id
JOIN stores s ON s.store_id = o.store_id
JOIN regions r ON r.region_id = s.region_id
JOIN products p ON p.product_id = oi.product_id
JOIN product_categories pc ON pc.category_id = p.category_id
WHERE o.order_status = 'Completed';
sql/04_powerbi_views.sql 
-- Analytics-ready FactSales View for Power BI Star Schema ingestion
CREATE OR REPLACE VIEW vw_powerbi_fact_sales AS
SELECT
    oi.order_item_id,
    o.order_id,
    DATE_TRUNC('day', o.order_datetime)::DATE AS date_key,
    o.customer_id,
    o.store_id,
    oi.product_id,
    o.order_channel,
    oi.quantity,
    ROUND(oi.quantity * oi.unit_price_at_sale * (1 - oi.discount_pct / 100.0), 2) AS net_revenue,
    ROUND(oi.quantity * oi.unit_cost_at_sale, 2) AS total_cost,
    ROUND(oi.quantity * oi.unit_price_at_sale * (1 - oi.discount_pct / 100.0) - oi.quantity * oi.unit_cost_at_sale, 2) AS gross_profit
FROM order_items oi
JOIN orders o ON o.order_id = oi.order_id
WHERE o.order_status = 'Completed';

Data Calculations

DAX Measure Library

Production DAX measures powering KPI cards, month-over-month growth calculations, and ratios.

01 / 11 CORE REVENUE KPI

Total Sales Revenue

Total Sales = 
SUM ( FactSales[net_revenue] )

Sums net revenue across the active filter context, providing the baseline top-line financial metric for executive dashboard views.

02 / 11 PROFITABILITY

Total Realized Profit

Total Profit = 
SUM ( FactSales[gross_profit] )

Calculates total net realized profit by aggregating line-item gross profit (Net Revenue minus Cost of Goods Sold).

03 / 11 MARGIN RATIO

Gross Profit Margin %

Profit Margin % = 
DIVIDE ( [Total Profit], [Total Sales], 0 )

Safe division measure computing net profit margin percentage, preventing divide-by-zero errors when evaluating filtered periods.

04 / 11 VOLUME METRICS

Total Orders Count

Total Orders = 
DISTINCTCOUNT ( FactSales[order_id] )

Counts unique completed customer transactions, enabling basket size and average spend calculation metrics.

05 / 11 TRANSACTION ANALYSIS

Average Order Value (AOV)

Average Order Value = 
DIVIDE ( [Total Sales], [Total Orders], 0 )

Tracks average monetary spend per transaction, helping identify high-value ordering channels and promotion performance.

06 / 11 TIME INTELLIGENCE

Sales Previous Month (PM)

Sales Previous Month = 
CALCULATE (
    [Total Sales],
    DATEADD ( DimDate[date_key], -1, MONTH )
)

Shifts the active filter context back by one month using DimDate, providing the baseline for MoM variance tracking.

07 / 11 GROWTH RATE

MoM Sales Growth %

MoM Sales Growth % = 
DIVIDE (
    [Total Sales] - [Sales Previous Month],
    [Sales Previous Month],
    0
)

Calculates percentage revenue expansion or contraction relative to the previous calendar month.

08 / 11 TIME INTELLIGENCE

Profit Previous Month (PM)

Profit Previous Month = 
CALCULATE (
    [Total Profit],
    DATEADD ( DimDate[date_key], -1, MONTH )
)

Shifts profit calculations to the preceding month, evaluating net earnings trajectory over time.

09 / 11 GROWTH RATE

MoM Profit Growth %

MoM Profit Growth % = 
DIVIDE (
    [Total Profit] - [Profit Previous Month],
    [Profit Previous Month],
    0
)

Monitors period-over-period net profit acceleration to ensure revenue growth translates into bottom-line earnings.

10 / 11 PRODUCTIVITY

Sales per Store Location

Sales per Store = 
DIVIDE (
    [Total Sales],
    DISTINCTCOUNT ( FactSales[store_id] ),
    0
)

Benchmarks physical store efficiency by normalizing sales volume across active regional store counts.

11 / 11 INVENTORY ANALYTICS

Inventory Turnover Ratio

Inventory Turnover = 
VAR UnitsSold = SUM ( FactSales[quantity] )
VAR AvgUnitsOnHand = AVERAGE ( FactInventory[units_on_hand] )
RETURN
    DIVIDE ( UnitsSold, AvgUnitsOnHand, 0 )

Measures inventory replacement velocity to prevent stock-outs and overstock holding costs.
